# Database

PostgreSQL in production; SQLite (in-memory, via `aiosqlite`) in tests for
speed. `app/db/base.py::GUID` is a platform-independent UUID type so the same
models work on both.

## Tables (implemented)

| Table | Notes |
|---|---|
| `organizations` | Tenant root. `slug` unique, `is_active`/`suspended_at` for super-admin suspension. |
| `permissions` | Fixed platform-wide capability catalog, not multi-tenant. Seeded by migration `0002`. |
| `roles` | Per-organization, unique on `(organization_id, slug)`. `is_system=True` for the 6 seeded default roles. |
| `role_permissions` | Many-to-many join table. |
| `teams` | Per-organization. |
| `users` | `organization_id` nullable (super admins only). Unique on `(organization_id, email)` — same email can exist in two different orgs. Soft delete. |
| `sessions` | One row per refresh token = one device. `refresh_token_hash` unique. |
| `one_time_tokens` | Email verification / password reset. `token_hash` unique, `purpose` discriminates. |
| `audit_logs` | Append-only. `before`/`after` JSON snapshots. |
| `lead_statuses` | Per-organization customizable pipeline stages. Unique on `(organization_id, key)`. |
| `leads` | Soft delete. FK to `lead_statuses`, `users` (assigned), `teams`. |
| `lead_activities` | Append-only timeline per lead. |

## Indexing

Every `organization_id` FK is indexed (the single most common filter).
Additionally indexed: `users.email`, `leads.phone`, `leads.email`,
`leads.source`, `leads.assigned_user_id`, `leads.status_id`,
`leads.next_follow_up_at`, `audit_logs.action`/`entity_type`/`entity_id`.

## Migrations

Alembic, hand-written (not autogenerated — the custom `GUID` type doesn't
autogenerate cleanly). `0001_initial` creates all tables; `0002_seed_permissions`
data-seeds the permission catalog. Run `alembic upgrade head` before starting
the app; `docker-compose.yml`'s backend service does this automatically.

To add a table/column: write the model, then hand-write the next revision
file the same way (`op.create_table` / `op.add_column` with explicit
`sa.Column` types) — don't rely on `--autogenerate` while `GUID` is a custom
type unless you also write a `render_item` hook for it.
